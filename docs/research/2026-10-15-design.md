# Clippings: visual and interaction design research

Date: 2026-10-15. Versions checked against npm and GitHub that day. Token values come from the Material Web token sources, the AndroidX Compose M3 sources and `@material/material-color-utilities` 0.4.0 run locally, because m3.material.io renders client-side and could not be fetched as text. Baseline: [stack and design research (2026-10-14)](./2026-10-14-stack-and-design.md), referred to below as "stack §N". This file covers design only and does not revisit the stack choices.

**Summary**
- **Color**: keep stack §1's Tonal Spot with a warm neutral override and spec 2021. There are four palettes: **olive** (default), **ochre**, **terracotta** and **ink**, which puts blue ink on warm paper. Contrast follows `prefers-contrast` plus a manual toggle, generated at levels 0, 0.5 and 1. Tags use 8 named colors, harmonized to each palette's seed.
- **Type**: **Literata** (serif with `opsz`, old-style figures and small caps) for headlines, clipping titles and reading text. **Roboto Flex** (`opsz`, `GRAD`) for UI. **Roboto Mono** for raw URLs. The M3 baseline scale is exposed as `typescale-*` utilities. The wordmark is Fraunces converted to SVG outlines.
- **Tokens**: `--md-sys-*` custom properties, generated plus static, are mapped through `@theme inline`. Tailwind's default color, font, radius, shadow, ease and breakpoint namespaces are reset. Breakpoints are M3 window classes (600/840/1200/1600). M3 springs are precomputed as CSS `linear()` curves.
- **Components**: everything is stable React Aria except **Toast** (`UNSTABLE_`), **TokenField** (alpha) and GridList/Tree **sections** (alpha). The clipping list is a `GridList`. Tags use `TagGroup` for display and `ComboBox selectionMode="multiple"` for editing. Use `Sheet` (new in 1.22) for the mobile drawer and bottom sheets. The Tailwind plugin is not needed.
- **Extension**: a **popup** (not the side panel) that saves when it opens, autosaves the note and tags, detects duplicates, and adds a context menu and a keyboard command. The toolbar icon changes state per tab. It shares `themes.css` and tokens with the web app.
- **Motion**: one shared-element morph (list to detail), directional navigation slides, an optional circular reveal for the theme switch, and `@starting-style` for overlays and new rows. The standard M3 motion scheme is used, with the expressive scheme only for the "saved" moment.
- **Illustration**: ink-line drawings with one tonal wash, colored by `currentColor` and theme variables. Icons are **Material Symbols Rounded** as a self-hosted subset font.

Screens below marked *(inferred)* come from stack §4, §9 and §10 (Google sign-in, ~5-user allowlist, MCP OAuth consent, background enrichment (QStash since the hosting change) with a `pending` state, `unique(user_id, url_normalized)` duplicate detection, a `source` field that includes `digest`, an extension saving through a bearer token). There is no brief or glossary in the repo yet.

## 1. Color

### 1.1 Scheme variants in material-color-utilities 0.4.0

`Variant` has 9 members: `MONOCHROME, NEUTRAL, TONAL_SPOT, VIBRANT, EXPRESSIVE, FIDELITY, CONTENT, RAINBOW, FRUIT_SALAD` (shipped `dynamiccolor/variant.d.ts`). Each has a `Scheme*` class taking `(sourceHct, isDark, contrastLevel, specVersion?, platform?)`. `contrastLevel` runs "from -1 to 1. -1 represents minimum contrast, 0 represents standard … and 1 represents maximum contrast" (`dynamic_scheme.d.ts`). The scheme exposes 59 `DynamicColor` roles, including `surfaceContainer*`, the `*Fixed` roles and the 2025 `*Dim` roles ([repo](https://github.com/material-foundation/material-color-utilities/tree/main/typescript)).

### 1.4 Contrast levels

Generated olive ratios (WCAG 2 relative luminance, computed from the scheme output):

| Pair | Std L | Std D | Medium (0.5) L | High (1) L |
|---|---|---|---|---|
| on-surface / surface | 16.3 | 14.3 | 17.9 | 20.0 |
| on-surface-variant / surface-container-high | 7.6 | 8.5 | 8.9 | 14.2 |
| primary / surface | 6.1 | 10.9 | 11.5 | 13.2 |
| outline / surface | 4.3 | 5.8 | 7.4 | 13.3 |
| outline / surface-container-high | 3.7 | 4.5 | — | — |
| **outline-variant / surface** | **1.6** | **2.0** | 4.9 | 8.6 |

- At standard contrast, `outline-variant` fails WCAG 1.4.11's 3:1 rule for UI components ([Understanding 1.4.11](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)). Use it **only for decorative dividers**. Field borders, unselected checkboxes and chip outlines that carry meaning use `outline`.
- Generate the three levels as `[data-contrast=standard|medium|high]`. Default to `medium` under `@media (prefers-contrast: more)` (supported in all targets: Chrome 96, Firefox 101, Safari 14.1, per MDN BCD 8.1.5). Settings offers "Standard / More / Most". Tailwind's `contrast-more:` variant is available for one-off tweaks ([states](https://tailwindcss.com/docs/hover-focus-and-other-states)).
- `forced-colors: active`: keep borders on cards, chips and fields (`border-color: CanvasText` via the `forced-colors:` variant), and don't rely on background-only selection.

### 1.5 Tag colors (custom colors with harmonization)

- In the library, `customColor(source, {value, name, blend})` uses the legacy `CorePalette` tones (40/100/90/10 light, 80/20/30/90 dark) and does not respond to contrast level (`utils/theme_utils.js`).
- `Blend.harmonize(design, source)` rotates the hue toward the seed by `min(diff × 0.5, 15°)` (`blend/blend.js`). This is M3's "harmonization" of custom colors.
- **Recommendation**: in the generator, harmonize each tag hue to each palette seed, then build `TonalPalette.fromHueAndChroma(hue, 36)` and take tones by contrast level yourself.

Olive results (container / on-container / dot):

|---|---|---|---|
| red | 27 → 42 | `#ffdbcd` / `#360f00` (13.3) / `#8e4d2f` | `#71361a` / `#ffdbcd` (7.3) / `#ffb596` |
| orange | 60 → 75 | `#ffddb3` / `#291800` / `#7f5610` | `#624000` / `#ffddb3` / `#f4bd6f` |
| amber | 91 → 100 | `#f6e388` / `#211b00` / `#6b5e10` | `#524700` / `#f6e388` / `#d8c76f` |
| green | 146 → 131 | `#ceeda2` / `#112000` / `#4d662a` | `#364e15` / `#ceeda2` / `#b3d089` |
| teal | 193 → 178 | `#a1f2db` / `#002019` / `#0b6b59` | `#005142` / `#a1f2db` / `#85d6c0` |
| blue | 255 → 240 | `#c8e6ff` / `#001e2e` / `#246488` | `#004c6d` / `#c8e6ff` / `#94cdf6` |
| violet | 305 → 320 | `#f8d8ff` / `#2d0b3d` / `#765085` | `#5d386b` / `#f8d8ff` / `#e4b7f3` |

- Every pair is ≥ 13:1 in light mode and ≥ 7.2:1 in dark mode.
- Store the tag color as a **name** (`tags.color text check (color in ('none','red',…))`), never as hex. The CSS then becomes `--tag-red-container: light-dark(…)` under each `data-palette`, and every palette and contrast level re-tints automatically.
- Use `none` (the default) for `surface-container-low` + `outline-variant`, so most tags stay quiet. Color is opt-in.
- Chips show the color as a 8px dot (`dot` tone) plus a tinted container. Never rely on color alone: the tag name is always shown.

### 1.6 State layers

M3 state-layer opacities: hover **0.08**, focus **0.10**, pressed **0.10**, dragged **0.16**, disabled content **0.38** (`_md-sys-state.scss` in Material Web; same values as the [M3 state layers page](https://m3.material.io/foundations/interaction/states/state-layers) cited in stack §1). Disabled containers use on-surface at 0.12 (M3 convention, *unverified* here).
- Implementation: one `::before` overlay per interactive surface, `background: currentColor` (the "on-" color), with opacity driven by React Aria's state attributes. Using the attributes rather than `:hover` means touch and keyboard behave the same ([RAC styling](https://react-aria.adobe.com/styling)):

  ```css
  @utility state-layer {
    position: relative; isolation: isolate;
    &::before { content: ""; position: absolute; inset: 0; border-radius: inherit;
      background: currentColor; opacity: 0; pointer-events: none; z-index: -1;
      transition: opacity var(--md-sys-motion-duration-short2) var(--md-sys-motion-easing-standard); }
    &[data-hovered]::before { opacity: var(--md-sys-state-hover-state-layer-opacity); }
    &[data-focus-visible]::before { opacity: var(--md-sys-state-focus-state-layer-opacity); }
    &[data-pressed]::before { opacity: var(--md-sys-state-pressed-state-layer-opacity); }
    &[data-dragging]::before { opacity: var(--md-sys-state-dragged-state-layer-opacity); }
  }
  ```
- For flat fills, `color-mix(in oklab, var(--md-sys-color-on-surface) 8%, var(--md-sys-color-surface))` is equivalent and keeps the snapshot simple in view transitions.

**Recommendation**: Tonal Spot, spec 2021, warm neutral override. Four palettes: olive (default), ochre, terracotta, ink. Three contrast levels, auto-raised by `prefers-contrast: more`. Eight harmonized, name-stored tag colors. `outline-variant` only for decoration. State layers via RAC `data-*` attributes.

### 2.2 Font choices

All are on Google Fonts and in `next/font`'s `font-data.json` (checked in `next@16.4.0`). Licenses are from the [google/fonts](https://github.com/google/fonts) repo directories. OpenType features were read from the upstream TTFs with fontTools.

| Use | Family | Axes (`next/font` metadata) | Useful features | License |
|---|---|---|---|---|
| **Brand / reading** | **Literata** | `opsz` 7–72, `wght` 200–900, italic | `onum lnum pnum tnum smcp c2sc frac dlig liga` | OFL |
| **UI (plain)** | **Roboto Flex** | `opsz` 8–144, `wght` 100–1000, `GRAD` −200–150, `wdth`, `slnt` + 9 parametric axes | `liga pnum` (default figures are tabular: all digits 1156 units) | OFL |
| **URLs / raw** | **Roboto Mono** | `wght` 100–700, italic | — | OFL |
| Wordmark only | Fraunces | `opsz` 9–144, `wght`, `SOFT` 0–100, `WONK` 0–1 | `liga ss01` (no old-style figures) | OFL |
| Alternatives considered | Newsreader (`opsz` 6–72; **no `onum` or `smcp`**), Source Serif 4 (`opsz` 8–60; full figure and small-cap set), Google Sans Flex (OFL, `opsz`, `wdth`, `ROND`, `tnum`), Inter (`opsz` 14–32, `tnum`) | | | OFL |

- **Why Literata**: it was designed for long-form screen reading, its `opsz` range covers both 11px labels and 57px display, and it is the only short-listed serif besides Source Serif 4 with old-style figures and small caps. Those suit the dates and acronyms in an editorial layout.
- Source Serif 4 is the fallback if Literata feels too bookish.
- Fraunces' `SOFT`/`WONK` personality is kept for the wordmark only, converted to outlines (§10). That avoids loading a third serif.

`next/font` setup (axes are opt-in: "By default, only the font weight is included"; [font API](https://nextjs.org/docs/app/api-reference/components/font)):

```ts
// apps/web/app/fonts.ts
import { Literata, Roboto_Flex, Roboto_Mono } from 'next/font/google';
export const serif = Literata({ subsets: ['latin'], axes: ['opsz'], variable: '--md-ref-typeface-brand' });
export const sans  = Roboto_Flex({ subsets: ['latin'], axes: ['opsz', 'GRAD'], variable: '--md-ref-typeface-plain' });
export const mono  = Roboto_Mono({ subsets: ['latin'], variable: '--md-ref-typeface-mono', preload: false });
// italic Literata: a second call with style: 'italic' if the array form is rejected for variable fonts (see Unverified)
```

The extension cannot use `next/font`. It imports `@fontsource-variable/roboto-flex` 5.3.0 (and `literata` 5.3.0 if the popup shows serif titles).

### 2.3 Reading typography

| Technique | Rule | Support (MDN BCD 8.1.5, targets of stack §7) |
|---|---|---|
| Measure | Reading column `max-inline-size: 66ch`; never above 80 characters ([WCAG 1.4.8](https://www.w3.org/WAI/WCAG22/Understanding/visual-presentation.html)) | all |
| Headings | `text-wrap: balance` | all |
| Body | `text-wrap: pretty` | Chrome 117, Safari 26, **not Firefox**: enhancement |
| Optical size | `font-optical-sizing: auto` (default) maps `opsz` to font size | all |
| Figures | Reading text: `font-variant-numeric: oldstyle-nums proportional-nums`. Dates and counts in UI: Roboto Flex's default tabular figures | all |
| Small caps | Acronyms in notes: `font-variant-caps: all-small-caps` (Literata has `c2sc`/`smcp`) | all |
| Ligatures | Default `liga` on; `dlig` off | all |
| Hanging punctuation | `hanging-punctuation: first allow-end last` | **Safari 26.5 only**: enhancement |
| Leading trim | `text-box: trim-both cap alphabetic` on buttons, chips and the wordmark row | Chrome 133, Firefox 154, Safari 18.2: all targets |
| Links in prose | `text-decoration-thickness: 1px; text-underline-offset: .2em`, color `primary` | all |
| Dark mode | Roboto Flex `GRAD` −25 (Material Symbols guidance for light-on-dark icons; [docs](https://developers.google.com/fonts/docs/material_symbols)); Literata `wght` −20 in dark mode (judgement) | all |

**Gotcha**: the CSS `font` shorthand resets `font-variant-*` and `font-optical-sizing` (but not `font-feature-settings`) ([MDN font](https://developer.mozilla.org/en-US/docs/Web/CSS/font)). Write the `typescale-*` utility with **longhands** (§3), or `oldstyle-nums` set on a parent gets wiped on every element that has a typescale class.

### 2.4 Paper texture and print

- **Grain**: see stack §1 (an `feTurbulence` SVG tile at 4–7% `multiply`, `soft-light` in dark mode). Add `@media (prefers-reduced-transparency: reduce), (forced-colors: active), print { body::before { display: none } }`. Reduced transparency is Chrome-only, which is harmless.
- **Edges**: no torn-paper images. A detail sheet gets `box-shadow: var(--shadow-1)` plus a 1px `outline-variant` hairline, and nothing more.
- **Print** (`@media print`):
  - `:root { color-scheme: light }`. Because all tokens are `light-dark()`, this alone gives light colors.
  - Hide the navigation, search, toolbars and grain.
  - `@page { margin: 18mm }`
  - `article { break-inside: avoid-page }`
  - Print the source URL after the title with `a.source::after { content: " — " attr(href) }`, in mono, body-small.
  - Keep tag dots with `print-color-adjust: exact` on `.tag-dot` only.

**Recommendation**: Literata + Roboto Flex + Roboto Mono, with Fraunces outlines for the wordmark. Use the M3 baseline scale plus two app roles (`reading`, `clipping-title`), a 66ch measure, balance for headings and pretty for body, old-style figures in prose and tabular figures in UI.

Static values, all from Material Web token sources:
- **Shape**: none 0, extra-small 4, small 8, medium 12, large 16, large-increased 20, extra-large 28, extra-large-increased 32, extra-extra-large 48, full 9999px (`_md-sys-shape.scss`).
- **Elevation levels** (dp): 0, 1, 3, 6, 8, 12. Web shadows, from `labs/gb/styles/elevation/md-elevation-tokens.scss`:
  - level 1: `0 1px 2px 0 shadow/.3, 0 1px 3px 1px shadow/.15`
  - level 2: `0 1px 2px 0 /.3, 0 2px 6px 2px /.15`
  - level 3: `0 1px 3px 0 /.3, 0 4px 8px 3px /.15`
  - level 4: `0 2px 3px 0 /.3, 0 6px 10px 4px /.15`
  - level 5: `0 4px 4px 0 /.3, 0 8px 12px 6px /.15`
- **Paper elevation rule**: tone carries hierarchy (stack §1). Shadows are used only for things that float: menus and popovers (level 2), dialogs, search view and snackbars (level 3). Cards and rows get level 0, and the elevated card gets level 1 at **half alpha** (`.15/.075`), so the paper looks laid flat. In dark mode shadows are nearly invisible, so the tonal steps do the work.
- **Focus indicator**: thickness 3px, outer offset 2px, inner offset −3px (`_md-sys-state-focus-indicator.scss`). Color is `secondary` (`_md-comp-focus-ring.scss`).
- **Breakpoints** (M3 window size classes; [Android docs](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)): compact < 600, medium 600–839, expanded 840–1199, large 1200–1599, extra-large ≥ 1600.

### 3.2 Tailwind 4 mapping (sketch)

Pattern: Material Web 2.5 `labs/gb/styles/tailwind.scss` (stack §1). `@theme inline` is needed because the values reference other variables ([Tailwind theme](https://tailwindcss.com/docs/theme)). `--x-*: initial` removes a default namespace.

```css
/* packages/ui/src/styles/index.css */
@import "tailwindcss";
@import "./themes.css";   /* generated: [data-palette][data-contrast] { --md-sys-color-*: light-dark(…); --tag-*: … } */
@import "./tokens.css";   /* static --md-sys-* (shape, typescale, elevation, state, motion) */

@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));   /* stack §11 */

@theme inline {
  --color-*: initial;
  --color-surface: var(--md-sys-color-surface);
  --color-surface-container-low: var(--md-sys-color-surface-container-low);
  /* …all 49 roles… */
  --color-tag-red: var(--tag-red-container);           /* bg-tag-red */
  --color-on-tag-red: var(--tag-red-on-container);

  --font-*: initial;
  --font-serif: var(--md-ref-typeface-brand);
  --font-sans: var(--md-ref-typeface-plain);
```

**Styling with Tailwind 4**: RAC exposes states as `data-*` attributes ([styling](https://react-aria.adobe.com/styling)). Tailwind 4 matches boolean data attributes natively: "you can just specify the attribute name", so `data-hovered:`, `data-pressed:`, `data-selected:`, `data-focus-visible:`; values need `data-[placement=top]:` ([Tailwind states](https://tailwindcss.com/docs/hover-focus-and-other-states)).
- `tailwindcss-react-aria-components` 2.2.0 (peer `tailwindcss ^4`) is described as optional ("also available to make styling states … easier"). It only shortens names (`pressed:` instead of `data-pressed:`).
- **Don't add it**, consistent with stack's "Changes to the brief". Native `data-*` variants are static strings that `@shadcn/lint` reads. Where a value variant repeats, define it once with `@custom-variant placement-top (&[data-placement=top]);`.
- RAC entering and exiting states (`data-entering`, `data-exiting`) on Popover, Modal and Tooltip drive CSS animations, and RAC waits for the animation to end before unmounting.

**i18n**: the Next.js setup in the docs reads `headers()` in the root layout ([frameworks](https://react-aria.adobe.com/frameworks)). That conflicts with Cache Components (stack §11). Hard-code `lang="en"` and `<I18nProvider locale="en-US">`.

**Recommendation**: use stable RAC everywhere. Wrap Toast in `packages/ui` because of its `UNSTABLE_` prefix. Postpone TokenField. Use Sheet for compact-width overlays. No Tailwind plugin.

## 6. Browser extension design

### 6.1 Popup vs side panel

| | Chrome | Firefox | Safari |
|---|---|---|---|
| Popup (`action.default_popup`) | 25×25 to **800×600** px ([action](https://developer.chrome.com/docs/extensions/reference/api/action)) | grows to 800×600 at most; fixed width in the overflow menu; set width on `<body>` ([MDN popups](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/user_interface/Popups)) | supported (Safari web extensions) |
| Side panel | `sidePanel` API, Chrome 114+, `open()` 116+ and only on a user action; `openPanelOnActionClick` ([sidePanel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel)) | `sidebar_action` (`default_panel`, `open_at_install` defaults to **true**) ([MDN](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/sidebar_action)) | not found (see Unverified) |
| WXT | `entrypoints/popup.html` | `entrypoints/sidepanel.html` maps to Chrome `side_panel` and Firefox `sidebar_action` ([WXT entrypoints](https://wxt.dev/guide/essentials/entrypoints.html)) | |

**Decision: popup.** Saving is a 3-second task, the popup works in all three browsers, and a side panel adds a permission and a Firefox auto-open on install. A side panel ("your clippings while you read") can be a later WXT entrypoint. Set `open_at_install: false` if you add it.

Popup lifecycle caveat: the document "is loaded every time the popup is shown, and unloaded every time the popup is closed", and clicking outside closes it (MDN). So **save on open and autosave edits**. Never hold unsaved state in the popup. Send edits to the service worker with `chrome.runtime.sendMessage`, and let the worker do the fetch (stack §4: fetch from the worker).

### 6.2 Save flow

1. Click the toolbar icon or press the shortcut. The popup opens and immediately sends `save(tab.url, tab.title)` through the worker. The `activeTab` permission gives the URL without broad `tabs` access.
2. The server upserts on `unique(user_id, url_normalized)` and returns `{status: 'created' | 'existing', clipping}`.
3. Shown states:
   - **created**: "Saved" + check, focus moves to the note.
   - **existing**: "Saved on 3 Oct", with the stored note and tags loaded.
4. Note (`TextArea`, `field-sizing: content`, 3–8 lines) and tags (`ComboBox` multi) autosave 400 ms after typing stops, and on blur. Status reads "Saving…" then "Saved".
5. "Done" (`window.close()`) or Esc. "Open in Clippings" opens `/c/[id]`.
6. When the user has selected text, prefill the note with it as a quote (`> …`). Reading the selection needs `scripting` + `activeTab` to run `getSelection()`.

Popup layout, 380px wide and about 300–460px tall:
- header 48px: small wordmark, account menu
- page block: favicon, title (serif title-medium, 2 lines), domain in mono label-small
- note and tag fields
- footer: status and Done

### 6.3 Context menu, keyboard, toolbar icon

- **Context menu** ([`contextMenus`](https://developer.chrome.com/docs/extensions/reference/api/contextMenus)): "Save page to Clippings" (`page`), "Save link to Clippings" (`link`, uses `linkUrl`), "Save selection as note" (`selection`). These run without UI, so feedback comes from the toolbar icon (below).
- **Commands**: `_execute_action` opens the popup, which saves. Add `save-silently` (save without UI). Shortcuts "must include either Ctrl or Alt", at most four suggested, and users remap them at `chrome://extensions/shortcuts` ([commands](https://developer.chrome.com/docs/extensions/reference/api/commands)). Suggested keys: `Alt+Shift+C` (open) and `Alt+Shift+S` (silent). Avoid `Ctrl+Shift+S`, which Firefox uses for screenshots (see Unverified).
- **Icon states, per tab** (`action.setIcon({tabId})`, `setBadgeText({tabId})`; badge text ≤ 4 characters, `setBadgeTextColor` Chrome 110+):

  | State | Icon | Badge |
  |---|---|---|
  | Default | outline clip | — |
  | This URL is saved | filled clip (`FILL` 1) | — |
  | Just saved (silent or context menu) | filled | "✓" for 2 s, `primary` from `tokens.json` |
  | Error / queued offline | outline | "!" on `error` |

  Checking whether the current tab is saved means sending every visited URL to your own server. Make that **opt-in** ("Show when a page is already saved"). Otherwise check only when the popup opens.
- Icons must be PNG (16/32/48/128); SVG isn't accepted for packed extensions (action docs). Firefox supports `theme_icons` (light/dark toolbar variants, WXT `manifest.theme_icons`). Chrome has no equivalent, so draw the clip with a mid-tone outline that works on both toolbars.

### 6.4 Shared theme

- `packages/ui` exports `index.css` (Tailwind and tokens), `themes.css`, `tokens.json`, the icon subset font, the RAC wrappers and the illustrations. WXT builds Tailwind with `@tailwindcss/vite` 4.3.3 and React with `@wxt-dev/module-react` 1.2.2.
- **Dark mode**: the popup is an ordinary document, so `color-scheme: light dark` + `light-dark()` follows the OS.
- **Palette**: read from `chrome.storage.sync`. The value is seeded from the user's server-side settings at sign-in and updated when the web app changes it, so the popup matches the web app with no flash. Set `data-palette` before React renders, using an inline-free module script in `popup.html`, because MV3 CSP forbids inline scripts.
- Fonts: bundle the Roboto Flex variable woff2 (fontsource) and the Material Symbols subset; skip Literata unless the popup uses serif titles.

**Recommendation**: a popup with save-on-open and autosave, duplicate-aware, a context menu with three entries, two commands, per-tab icon state, and the same `packages/ui` tokens. Side panel later, if at all.

- **Card vs list**: list by default (an editorial index on paper, hairline dividers). - **Mobile details**:
  - `viewport-fit=cover`, plus `env(safe-area-inset-*)` padding on the bars
  - `100dvh` for full-height sheets
  - 48px touch targets on bars
  - no hover-only actions: the row menu button is always visible on touch (`@media (hover: none)`)

## 8. Transitions

Optionally a **circular reveal** from the toggle: animate `clipPath` on `::view-transition-new(root)` from `circle(0 at x y)` to the far-corner radius in `transition.ready` ([Chrome docs](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)). 400 ms, emphasized-decelerate | React "interrupts" view transitions started by other code (React docs). Keep it short and don't switch the theme during navigation. Without `startViewTransition` support, switch instantly |
| **Overlays** (menu, popover, dialog, sheet, tooltip) | CSS on RAC `data-entering`/`data-exiting` + `@starting-style`. Not view transitions | Avoids a snapshot of the whole page on every menu open |
| **Toasts** | RAC's documented `ToastQueue({ wrapUpdate })` uses `startViewTransition` + `flushSync` with `view-transition-class: toast` ([Toast](https://react-aria.adobe.com/Toast)) | Can collide with React-driven view transitions (see Unverified). Fallback: `@starting-style` slide-in, no exit animation |
| **List add/remove** (delete with Undo) | Per-row `<ViewTransition key={id}>` (bare, so `update` reflows neighbours), delete inside `startTransition` | Use committed state, not `useOptimistic`, for order (skill troubleshooting) |

**Reduced motion**:
- Under `prefers-reduced-motion: reduce`, keep crossfades. Chrome's guide notes reduced motion "doesn't mean the user wants *no motion*".
- Remove slides, the morph's position and scale movement, and the circular reveal: set `::view-transition-group(*) { animation-duration: 0s }` and keep `::view-transition-old/new(*)` fades at 150 ms.
- React does not disable view transitions automatically (React docs).
- Also add `::view-transition { pointer-events: none }` (stack §8).

Note: the repo's view-transitions skill still says to install `react@canary` without Next. That is outdated since React 19.3 (stack §8); within Next it doesn't apply.

**Recommendation**: four uses only: the list↔detail sheet morph, nav-forward/back slides, Suspense crossfades, and the theme reveal. Everything else is CSS (`@starting-style`, RAC `data-entering`).

## 9. Motion

### 9.1 Tokens

From `_md-sys-motion.scss` (Material Web, latest token version):

| Token | Value |
|---|---|
| duration short 1–4 | 50, 100, 150, 200 ms |
| duration medium 1–4 | 250, 300, 350, 400 ms |
| duration long 1–4 | 450, 500, 550, 600 ms |
| duration extra-long 1–4 | 700, 800, 900, 1000 ms |
| easing standard | `cubic-bezier(0.2, 0, 0, 1)` |
| standard-decelerate / -accelerate | `cubic-bezier(0, 0, 0, 1)` / `cubic-bezier(0.3, 0, 1, 1)` |
| emphasized | aliased to standard in the CSS tokens (the real emphasized curve is a path, which CSS can't express) |
| emphasized-decelerate / -accelerate | `cubic-bezier(0.05, 0.7, 0.1, 1)` / `cubic-bezier(0.3, 0, 0.8, 0.15)` |

Springs (damping ratio / stiffness), from the same file for standard and from AndroidX `ExpressiveMotionTokens.kt` / `StandardMotionTokens.kt` ([androidx](https://github.com/androidx/androidx/tree/androidx-main/compose/material3/material3/src/commonMain/kotlin/androidx/compose/material3/tokens)):

| Spring | Standard scheme | Expressive scheme |
|---|---|---|
| fast spatial | 0.9 / 1400 | 0.6 / 800 |
| default spatial | 0.9 / 700 | 0.8 / 380 |
| slow spatial | 0.9 / 300 | 0.8 / 200 |
| fast / default / slow effects | 1.0 / 3800, 1600, 800 | same |

These **correct stack §1's motion row**, which listed cubic-bezier approximations without stiffness values.

### 9.2 Springs as CSS `linear()`

`linear()` is supported in all targets (Chrome 113, Firefox 112, Safari 17.2). The curves below are sampled from the damped-oscillator solution with mass 1, cut where the spring stays within 0.2% of rest. This is my calculation, not an M3 artifact:

```css
:root {
  /* standard default spatial (0.9 / 700): ~220 ms */
  --md-sys-motion-spring-default-spatial: linear(0, 0.036, 0.12, 0.227, 0.342, 0.452, 0.554, 0.643, 0.719, 0.783, 0.835, 0.876, 0.909, 0.934, 0.954, 0.968, 0.979, 0.986, 0.992, 0.996, 1);
  --md-sys-motion-spring-default-spatial-duration: 220ms;
  /* default effects (1.0 / 1600): ~210 ms, no overshoot; for opacity and color */
  --md-sys-motion-spring-default-effects: linear(0, 0.158, 0.413, 0.626, 0.773, 0.868, 0.925, 0.958, 0.977, 0.987, 0.993, 0.996, 1);
  --md-sys-motion-spring-default-effects-duration: 210ms;
  /* expressive default spatial (0.8 / 380): ~410 ms, 1.5% overshoot. Only for the "saved" check and the chip-add pop */
  --md-sys-motion-spring-expressive-spatial: linear(0, 0.065, 0.209, 0.377, 0.539, 0.678, 0.789, 0.872, 0.931, 0.97, 0.994, 1.007, 1.014, 1.015, 1.014, 1.012, 1.01, 1.007, 1.005, 1.003, 1);
  --md-sys-motion-spring-expressive-spatial-duration: 410ms;
}
```

Store the raw damping and stiffness in the generator and emit the curves, so they can be re-derived.

### 9.3 What moves

| Element | Motion | Token |
|---|---|---|
| State layers (hover, press) | opacity | short2 (100 ms), standard |
| Menus, popovers, tooltips | fade + 4px translate from the anchor side (`data-placement`) | enter short4 / emphasized-decelerate, exit short3 / emphasized-accelerate |
| Dialog | fade + scale .96 → 1 | medium2 enter, short3 exit |
| Sheet (mobile) | RAC Sheet uses native scroll gestures; only style the backdrop fade | — |
| Top app bar on scroll | `surface` → `surface-container` | `animation-timeline: scroll()` under `@supports` (Firefox has no scroll-driven animations, stack §7), otherwise an `IntersectionObserver` sentinel toggles `data-scrolled` |
| Nav indicator / theme toggle indicator | `SelectionIndicator` slide | default spatial spring |
| New rows, toasts | `@starting-style { opacity: 0; translate: 0 4px }` | default effects |
| Saved check (extension, new clipping) | stroke draw + expressive spring scale | expressive spatial |
| Skeletons | static (no shimmer) | — |
| Icons on select | Material Symbols `FILL` 0 → 1 via `font-variation-settings` transition | short3 |

- **Reduced motion**: a global `@media (prefers-reduced-motion: reduce) { *, ::before, ::after { animation-duration: 1ms; transition-duration: 1ms; scroll-behavior: auto } }`. Keep opacity fades, which are below the vestibular threshold. Tailwind's `motion-safe:` gates any decorative animation.
- `interpolate-size` / `calc-size()` work only in Chrome, so animate disclosure height with `grid-template-rows: 0fr → 1fr` instead.

**Recommendation**: the standard M3 motion scheme throughout, the expressive spring only for "saved" feedback, `linear()` springs as tokens, CSS for overlays, and reduced motion keeping fades.

## 10. Illustration, icons and app icon

### 10.1 Illustration style

M3 has no illustration guidance (stack §1). Proposed style, **"ink and wash"**:
- Single-weight line art: 1.5px stroke at 1×, `vector-effect: non-scaling-stroke`, round caps and joins, `stroke="currentColor"` (set to `on-surface-variant`).
- **One** flat wash in `var(--md-sys-color-secondary-container)` or `tertiary-container`, offset 2–3px from the line, like a misregistered print.
- The paper grain shows through. No gradients, no raster images.
- Motifs from the clipping world: paper clips, scissors along a dotted line, a newspaper column, index cards, a pushpin, a magnifier, a letterbox.

| Where | Scene | Size |
|---|---|---|
| Empty list | An open notebook with a single paper clip | 200px |
| No results | A magnifier over a blank clipping | 160px |
| Sign in | A small stack of pinned clippings | 240px |
| Not allowlisted | A letterbox with a "members" card | 200px |
| 404 | A page with a torn corner | 200px |
| Offline | A paper airplane resting on the ground | 160px |
| Extension onboarding | Scissors cutting a page along a dotted line | 240px |
| Error | A torn strip held by tape | 160px |

- Ship them as React components in `packages/ui/illustrations` (inline SVG, `aria-hidden="true"`, each ≤ 3 KB after SVGO, `viewBox` only).
- They re-tint per palette, mode and contrast automatically. In `forced-colors` mode, `currentColor` becomes `CanvasText` and the wash disappears, which is acceptable.
- Optional first-view animation: stroke-draw via `stroke-dasharray`, behind `motion-safe:`.

### 10.2 Icon set

| | Material Symbols (Rounded) | Lucide | Phosphor |
|---|---|---|---|
| License | Apache 2.0 | ISC | MIT |
| Package | Google Fonts CSS2 / self-host; `@material-symbols/svg-400` 0.48.0 (SVG); `@fontsource-variable/material-symbols-rounded` 5.3.9 (full font) | `lucide-react` 1.57.0 | `@phosphor-icons/react` 2.1.10 |
| Variability | Variable font: `FILL` 0–1, `wght` 100–700, `GRAD`, `opsz` 20–48 ([docs](https://developers.google.com/fonts/docs/material_symbols)) | Stroke width prop | 6 weights incl. duotone |
| Fit | Native to M3 (nav-indicator `FILL`, `GRAD` −25 in dark mode); Rounded suits paper | Thin strokes suit editorial but not M3 | Duotone fits ink-and-wash, but mixes poorly with M3 components |
| Bundle | Font subset by `icon_names` (alphabetical list): "295 KB to 1.7 KB" for 3 icons in Google's example | Tree-shaken SVG components | Tree-shaken |

**Choice: Material Symbols Rounded as a self-hosted subset font.**
- A build script requests `fonts.googleapis.com/css2?family=Material+Symbols+Rounded:opsz,wght,FILL,GRAD@20..24,300..500,0..1,-25..0&icon_names=<sorted list>`, downloads the woff2 into `packages/ui/fonts/`, and loads it with `next/font/local` (`display: 'block'` to avoid flashing ligature text, as the docs advise). The extension uses the same file.
- A CI check fails if an `<Icon name>` isn't in the list.
- Fallback if the subset API becomes a problem: `@material-symbols/svg-400` SVGs (outline and `-fill` variants, no axis animation).
- Note that Material Symbols is **not** in `next/font/google`'s font list (checked `font-data.json` in next 16.4.0).

### 10.3 App icon, favicon, wordmark

- **Mark**: a rounded square (M3 extra-large corner proportion) in `primary-container`, holding a paper clip drawn as one continuous `on-primary-container` stroke, bent into a "C". The same glyph serves as the extension toolbar icon (outline and filled variants, §6.3).
- **Files** (Next metadata conventions): `app/icon.svg` with an internal `@media (prefers-color-scheme: dark)`, `app/icon.png` 32px fallback, `app/apple-icon.png` 180px (opaque, light paper background), and `app/manifest.ts` with `theme_color` and `background_color` from `tokens.json` ([app icons](https://nextjs.org/docs/app/api-reference/file-conventions/metadata/app-icons)).
- `viewport.themeColor` takes two entries keyed by `prefers-color-scheme`, from `tokens.json`.
- **Wordmark**: "Clippings" in Fraunces italic, `opsz` 144, `SOFT` 100, `WONK` 1, weight ~500, converted to outlines (SVG, `fill="currentColor"`). That costs no font request; OFL fonts may be used for logos.
- Optional detail: a small scissor-cut notch on the "C".

**Recommendation**: ink-and-wash SVG components colored by tokens, Material Symbols Rounded as a self-hosted subset font, and a paper-clip "C" mark with an outlined Fraunces wordmark.

## 11. Accessibility, microcopy, density and loading

**Accessibility**
- **Contrast**: §1.4 numbers. Body and labels at standard contrast are ≥ 7:1 on every container (on-surface-variant on surface-container-high is 7.6). Primary as text is 6.1:1 in light mode.
- **Focus**: RAC's `data-focus-visible` (keyboard only) drives an `outline: 3px solid var(--md-sys-color-secondary); outline-offset: 2px` (M3 focus indicator, §3.1). `secondary` vs surface is 6.1:1 (light) and 10.9:1 (dark). For non-RAC elements use `:focus-visible` (all targets).
  - Sticky top bars must not hide the focused row: `scroll-padding-top: 64px` ([WCAG 2.4.11 Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)).
- **Target size**: WCAG 2.2 AA asks for 24×24 CSS px ([2.5.8](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)). Use 48px hit areas for bar and rail items and 40px icon buttons (the M3 small icon button, 32px visual plus padding). Chips: 32px tall with a vertical touch extension via `::after { inset: -8px 0 }`.
- **Landmarks**: `header`, `nav` (rail/bar), `main`, the Toast region (F6), and a skip link to `main`.
- **Live regions**: autosave status uses `role="status"` (polite). Errors go in `FieldError`, plus a toast only for background failures.
- **Color is never the only signal**: tags show names; pending is shown by text and a bar, not just grey.

**Microcopy tone**: plain and warm, a little bookish; no exclamation marks.
- Verbs: "Save", "Saved", "Open original", "Delete", "Undo".
- Use "clipping" (noun) consistently, and record it in `GLOSSARY.md` when it is created (AGENTS.md: domain docs).
- Examples:

  | Moment | Copy |
  |---|---|
  | Empty list | "Nothing clipped yet. Save a page with the extension, ask Claude to clip something, or drop a link here." |
  | No results | "No clippings match "*q*". Try fewer words or clear the tag filter." |
  | Pending | "Reading the page…" |
  | Failed | "Couldn't read this page. Your link and note are saved." |
  | Duplicate | "Already saved on 3 Oct." |
  | Delete toast | "Clipping deleted." with an "Undo" action |
  | Offline | "You're offline. Changes are paused." |
  | Consent | "Claude wants to save and search your clippings." |

- Dates: relative for under 7 days ("2 days ago"), otherwise "3 Oct" or "3 Oct 2025" via date-fns with a `<time datetime>` (stack §2).

**Density**: comfortable by default; compact as a setting (§7). Stored per user, applied as `data-density` on `<html>` by the same no-flash script as theme and palette (stack §11).

**Loading**
- Route-level `loading.tsx` skeletons copy the exact row geometry: `surface-container-high` blocks at radius 4, no shimmer, appearing after a 150 ms delay (`animation-delay`) so fast loads show nothing.
- Search in flight: a 2px indeterminate `ProgressBar` under the search field, with previous results dimmed.
- Buttons doing work: label + spinner and `isPending` (RAC `Button` has `isPending`).

**Wordmark and logo ideas**:
1. The clip-"C" mark with the Fraunces italic wordmark (recommended).
2. Small-caps "CLIPPINGS" in Literata `c2sc` with a dotted cut-line underline.
3. A scissor glyph replacing the "i" dots.

## Unverified / could not confirm

- m3.material.io pages render client-side and could not be read as text. M3 values come from Material Web's generated token files, MDC-Android docs and AndroidX sources instead. Disabled container opacity (0.12) is from memory of M3, not a fetched source.
- **Sheet** (1.22), **NavigationTree** (1.21), **PreviewTrigger**, **SelectionIndicator** and **SharedElementTransition**: the docs and release notes give no alpha/beta label, and they export without `UNSTABLE_`. Treated as stable, but they are new.
- Whether RAC Toast's `wrapUpdate` (`startViewTransition` + `flushSync`) and a manual theme-switch `startViewTransition` coexist with React's `<ViewTransition>`. React says it interrupts external view transitions. Prototype this.
- The text-morph recipe (`object-fit: none` on title snapshots) needs a prototype.
- Safari support for extension side panels (`sidePanel` or `sidebar_action`): no Apple source found.
- Whether `next/font/google` accepts `style: ['normal','italic']` for a variable font (the docs describe arrays only for non-variable fonts).
- OpenType features were read from the upstream TTFs in google/fonts. It is not confirmed that the files `next/font` downloads from the Google Fonts API keep `onum`/`smcp`/`c2sc`.
- Google Sans Flex: Google Fonts metadata lists a `GRAD` axis, but the TTF's `fvar` doesn't.
- Firefox `Ctrl+Shift+S` (screenshots) conflict, and whether `Alt+Shift+C/S` are free in all three browsers.
- An SVG favicon with an internal `prefers-color-scheme` query in Safari 26.6/27.
- Literata variable font file sizes per subset (not measured).
- The spring `linear()` curves are my numerical approximation, not M3-published CSS.
- The Material Symbols CSS2 `icon_names` subset combined with axis ranges in one request (the docs show both, but the exact combined URL wasn't tested).
